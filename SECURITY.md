# Безопасность

Разбор проведён по коду целиком: API, портал, приложение. Ниже — что
закрыто, чем это проверяется и что осталось осознанным риском.

## Закрыто

### Доступ к чужим данным

До guard'ов в контроллерах не было ни одного: зная идентификатор агентства,
кто угодно открывал чужой кабинет и переписывал там цены. Теперь доступ к
агентству — это членство (`AgencyMember`), а не просто наличие входа.

Три guard'а по тому, откуда берётся агентство: из адреса (`AgencyGuard`),
из фида (`FeedGuard`), из заявки (`LeadGuard`). Кабинет собственника и
аватар проверяются на совпадение с вошедшим.

Проверяется `test/access.spec.ts`: без токена 401, с чужим токеном 403,
подделанная подпись 401, витрина при этом 200.

### SSRF в фидах

Адрес фида присылает агентство, а идём по нему мы — со своего сервера.
Строковая проверка имени не защищала: мимо неё проходили `172.16/12`, адрес
числом (`http://2130706433/` — это `127.0.0.1`), имя, разрешающееся во
внутренний IP, и редирект с публичной ссылки на `169.254.169.254`
за метаданными облака.

Теперь имя разрешается в адреса, каждый проверяется по списку закрытых
диапазонов (IPv4 и IPv6, включая отображённые), редиректы проходятся вручную
с проверкой каждого шага и ограничением в три перехода. Тело читается с
ограничением по ходу чтения: заголовку `content-length` верить нельзя.

Проверяется `test/url-safety.spec.ts`.

### Перебор кода входа

Шесть цифр — это миллион вариантов. Без ограничений их перебирают за минуты.
Теперь: пять попыток на код, затем он сгорает; новый код не чаще раза в
полминуты; пять запросов кода в минуту с адреса и десять попыток входа.

### Подделка токенов

`AUTH_SECRET` короче 16 символов или не задан — в проде API не поднимается
вовсе. Подняться с предсказуемым ключом хуже, чем не подняться.

### Прочее

- Заголовки безопасности через `helmet`; CSP для API выключена намеренно —
  он отдаёт JSON и картинки, своя политика у портала.
- Ограничение частоты на весь API: 120 запросов в минуту, на входе и
  загрузке файлов — жёстче.
- Тело запроса ограничено 256 КБ, загрузка файлов — 2 МБ.
- Загрузка проверяет тип по сигнатуре файла, а не по заголовку клиента;
  SVG отвергается при найденном скрипте; имя генерируется, присланное не
  используется; удаление отказывает на `/` и `..` в имени.
- Валидация тел запросов с `whitelist` и `forbidNonWhitelisted`: лишние
  поля не проходят.
- Сырых SQL-запросов нет, кроме `SELECT 1` в проверке живости.
- `dangerouslySetInnerHTML` на портале не используется; HTML всплывающей
  карточки на карте экранируется.

## Осознанный риск

**Рыночную цену указывает агентство.** Витрина проверяет только то, что
цена ниже указанной рыночной. Агентство может завысить рыночную и получить
фальшивую скидку. Решается индексом цен по районам — он пока не построен.

**Уязвимости в зависимостях сборки.** `npm audit --omit=dev` показывает
38 находок. Все приходят из инструментов сборки Expo (`@expo/config`,
`@expo/prebuild-config`) и Next (`postcss`), на сервер не попадают и
запросом не достигаются. Единственная, доходящая до API, — `deepmerge-ts`
внутри `@prisma/config`, он читает наш же конфиг на этапе CLI. Исправления
требуют мажорных обновлений Expo и отложены.

**Коды входа хранятся в памяти процесса.** При нескольких экземплярах API
код, выданный одним, не узнает другой. До горизонтального масштабирования
нужно вынести в Redis.

**Отзыв токенов не предусмотрен.** Токен живёт 30 дней и действует до
истечения. Смена `AUTH_SECRET` отзывает все сразу.

**Отправка кодов заглушена.** В dev-режиме код возвращается в ответе API.
В проде (`NODE_ENV=production`) не возвращается, но и не отправляется:
провайдера SMS и почты ещё нет.
