# Casaya

Портал недвижимости Коста-Бланки: проверенный инвентарь, сервисный слой сделки
для иностранных покупателей и автоматическое наполнение из CRM агентств.

Фронтенд повторяет макет `Casaya Portal.html` один в один — те же секции,
отступы, цвета, типографика и состояния.

## Стек

- **apps/web** — Next.js 16 (App Router) + TypeScript + React 19
- **apps/api** — NestJS 11 + Prisma 6 + PostgreSQL
- **apps/mobile** — Expo 54 + React Native 0.81 + expo-router
- **docker-compose.yml** — Postgres для локальной разработки (`casaya-db`, порт **5433**)

## Запуск

```bash
npm install

# 1. База (свой контейнер, порт 5433 — не конфликтует с другими проектами)
npm run db:up

# 2. Схема и демо-данные макета
npm run db:migrate
npm run db:seed

# 3. API и фронтенд (в двух терминалах)
npm run dev:api   # http://localhost:4100/api
npm run dev:web   # http://localhost:3100
```

Переменные окружения: `apps/api/.env.example`, `apps/web/.env.example`, `apps/mobile/.env.example`.

## Приложение

```bash
cd apps/mobile
npx expo run:ios       # первая сборка ~10 минут, дальше — npx expo start
```

Нужен **development build**, не Expo Go: карта использует нативный MapLibre.
На реальном телефоне `localhost` не сработает — в `apps/mobile/.env` подставьте
IP компьютера в локальной сети:

```
EXPO_PUBLIC_API_URL=http://192.168.1.5:4100/api
EXPO_PUBLIC_ASSETS_URL=http://192.168.1.5:4100
```

Экраны: главная, выдача, карта, объявление, избранное, сделка, ипотека, чат, профиль.
Вкладки — плавающая панель из макета: активная раскрывается и показывает подпись.

## Языки

Восемь локалей: **ES · EN · RU · NL · DE · FR · PL · SV** — испанский как язык
рынка плюс языки покупателей из бизнес-плана (нидерландцы — №1 среди
не-резидентов Коста-Бланки).

Каждая страница живёт под префиксом языка: `/es`, `/en`, `/ru/search`,
`/nl/listing/...`. Корень редиректит по заголовку `Accept-Language`, а если
посетитель переключался вручную — по его выбору из cookie. Испанский —
запасной вариант.

Переключатель в шапке меняет префикс в текущем адресе, а не уводит на главную.

Для SEO: `hreflang` на все восемь языков плюс `x-default`, canonical на каждой
странице, `sitemap.xml` с перекрёстными языковыми ссылками (128 URL).
Разряды чисел форматируются по локали: `€485,000` · `485.000 €` · `485 000 €`.

Словари — `apps/web/src/i18n/dictionaries/`. Русский исходный: из него выводится
тип `Dictionary`, поэтому пропущенный ключ в любом языке ломает сборку.

## Интеграция агентств

Инвентарь приходит из XML-выгрузок CRM (Inmovilla, Witei, Mobilia,
Resales Online, Kyero). Агентство вставляет ссылку на фид, видит сухой прогон
и подключается; дальше объекты обновляются сами.

Подробно: [docs/feeds.md](docs/feeds.md). Справочник API: [docs/api.md](docs/api.md).

## Модель данных

`Listing`, `Agency`, `AgencyFeed`, `FeedRun`, `Project`, `City`, `Bank`, `Plan`,
`ServiceOffer`, `User`, `Favorite`, `Lead`, `Valuation` — см. `apps/api/prisma/schema.prisma`.

## Карта

Поиск и страница объекта используют **MapLibre GL** с векторной подложкой
CARTO Positron — светлой и почти монохромной, чтобы она не спорила с пинами
и карточками. Ключ API не нужен.

Пины — те же ценовые «таблетки», что в макете: белые, фиолетовые у выбранного,
с терракотовой обводкой у объектов в избранном. Наведение на карточку выдачи
подсвечивает пин и наоборот; клик по пину открывает мини-карточку объекта.
Карта показывает ровно то, что в выдаче, и приближается только с Cmd/Ctrl,
чтобы не перехватывать прокрутку страницы.

Координаты объектов приходят из фидов агентств (`lat`/`lng` в выгрузке CRM).
Объекты без координат на карту просто не попадают.

В приложении — тот же MapLibre и тот же стиль CARTO через
`@maplibre/maplibre-react-native`. Apple Maps и Google Maps отпали сразу:
подложку Apple Maps нельзя перекрасить под макет, а Google Maps требует ключ
и выглядит на iOS и Android по-разному.

Воркер тайлов MapLibre копируется в `public/vendor/maplibre/` скриптом
`apps/web/scripts/copy-maplibre-worker.mjs` перед `dev` и `build`: бандлер его
не эмитит, и без этого карта остаётся пустой.

## Решения, о которых стоит знать

- **Дизайн переносится инлайновыми стилями.** Значения взяты из макета без
  переосмысления. Единственное, что вынесено в `globals.css`, — ховеры
  (атрибут `style-hover` в макете нельзя выразить инлайном).
- **Числа форматируются вручную** (`groupDigits`), а не через `toLocaleString`:
  так разметка на сервере и в браузере совпадает и гидрация не ломается.
- **Импорт из фида не выдаёт бейдж Verificado.** Он появляется только после
  nota simple и видео-тура — это и есть «solo pisos reales».
- **Пропавшие из фида объекты архивируются, а не удаляются** — на них есть отклики.
- **Избранное анонимного посетителя** живёт в localStorage (в приложении —
  AsyncStorage) и переносится в аккаунт через `POST /favorites/merge` после входа.
- **Демо-фото отдаёт API** (`apps/api/public/img`), а не фронтенд: приложению
  тогда нужен один адрес вместо двух. Фото из агентских фидов — абсолютные
  ссылки на их CDN, они идут мимо.
- **Типы объектов различают виллу и дом, студию и квартиру** — так устроен
  испанский рынок и так фильтрует приложение. На портале пресет «Дома»
  по-прежнему включает виллы и таунхаусы, «Квартиры» — студии и пентхаусы.
