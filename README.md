# Casaya

Портал недвижимости Коста-Бланки: проверенный инвентарь, сервисный слой сделки
для иностранных покупателей и автоматическое наполнение из CRM агентств.

Фронтенд повторяет макет `Casaya Portal.html` один в один — те же секции,
отступы, цвета, типографика и состояния.

## Стек

- **apps/web** — Next.js 16 (App Router) + TypeScript + React 19
- **apps/api** — NestJS 11 + Prisma 6 + PostgreSQL
- **apps/mobile** — Expo 54 + React Native 0.81 + expo-router
- **docker-compose.yml** — Postgres для локальной разработки (`casaya-db`, порт **5433**)

## Запуск

```bash
npm install

# 1. База (свой контейнер, порт 5433 — не конфликтует с другими проектами)
npm run db:up

# 2. Схема и демо-данные макета
npm run db:migrate
npm run db:seed

# 3. API и фронтенд (в двух терминалах)
npm run dev:api   # http://localhost:4100/api
npm run dev:web   # http://localhost:3100
```

Переменные окружения: `apps/api/.env.example`, `apps/web/.env.example`, `apps/mobile/.env.example`.

## Приложение

```bash
cd apps/mobile
npx expo run:ios       # первая сборка ~10 минут, дальше — npx expo start
```

Нужен **development build**, не Expo Go: карта использует нативный MapLibre.
На реальном телефоне `localhost` не сработает — в `apps/mobile/.env` подставьте
IP компьютера в локальной сети:

```
EXPO_PUBLIC_API_URL=http://192.168.1.5:4100/api
EXPO_PUBLIC_ASSETS_URL=http://192.168.1.5:4100
```

Экраны: главная, выдача, карта, объявление, избранное, сделка, ипотека, чат, профиль.
Вкладки — плавающая панель из макета: активная раскрывается и показывает подпись.

## Языки

Восемь локалей: **ES · EN · RU · NL · DE · FR · PL · SV** — испанский как язык
рынка плюс языки покупателей из бизнес-плана (нидерландцы — №1 среди
не-резидентов Коста-Бланки).

Каждая страница живёт под префиксом языка: `/es`, `/en`, `/ru/search`,
`/nl/listing/...`. Корень редиректит по заголовку `Accept-Language`, а если
посетитель переключался вручную — по его выбору из cookie. Испанский —
запасной вариант.

Переключатель в шапке меняет префикс в текущем адресе, а не уводит на главную.

Для SEO: `hreflang` на все восемь языков плюс `x-default`, canonical на каждой
странице, `sitemap.xml` с перекрёстными языковыми ссылками (128 URL).
Разряды чисел форматируются по локали: `€485,000` · `485.000 €` · `485 000 €`.

Словари — `apps/web/src/i18n/dictionaries/`. Русский исходный: из него выводится
тип `Dictionary`, поэтому пропущенный ключ в любом языке ломает сборку.

## Интеграция агентств

Инвентарь приходит из XML-выгрузок CRM (Inmovilla, Witei, Mobilia,
Resales Online, Kyero). Агентство вставляет ссылку на фид, видит сухой прогон
и подключается; дальше объекты обновляются сами.

Подробно: [docs/feeds.md](docs/feeds.md). Справочник API: [docs/api.md](docs/api.md).

## Дубли: один объект — несколько агентств

Одну квартиру на Коста-Бланке обычно продают 5–10 агентств сразу. На обычных
порталах это пять одинаковых карточек в выдаче — та самая боль, против которой
построен весь продукт.

В базе разведены две сущности:

- **`Property`** — реальный объект: адрес, координаты, площадь, комнаты,
  этаж, кадастровый номер.
- **`Listing`** — предложение одного агентства по этому объекту: своя цена,
  своё описание, свои фотографии.

Импорт фида для каждого объявления ищет подходящий `Property`
(`apps/api/src/properties/match.ts`):

1. **Кадастровый номер** — официальный идентификатор, решает сам.
2. Иначе отбираются кандидаты по координатной окрестности и ключу
   «город + тип + площадь + спальни».
3. Каждый кандидат получает оценку схожести: расстояние (38%), площадь (24%),
   адрес (20%), спальни (12%), санузлы (6%). Порог склейки — **0,72**.

Жёсткие несовпадения сразу дают ноль: разный тип, разница площади больше 12%,
дальше 300 метров, разные этажи. Лучше показать два объявления, чем склеить
разные квартиры.

В выдаче остаётся одна карточка на объект — проверенная, при равенстве самая
дешёвая — с пометкой «Продают N агентства». На странице объекта все предложения
сравниваются по цене с разбросом и отметкой «Дешевле всех».

## Чьи фотографии показывать

Одну квартиру три агентства снимают по-разному, и в общей карточке нужно
решить, чьи кадры показать.

- **Оплаченный показ** — всегда фотографии того агентства, которое заплатило.
  Это его показ, его съёмка, его условия.
- **Обычная карточка** — лучший набор по объекту. Качество считает
  `photoSetScore`: проверка Casaya весит 45% (съёмка шла по нашему чек-листу),
  количество кадров 35% (восемь дают полную картину, два — нет), видео-тур 20%.
  Иначе слабая съёмка одного агентства топила бы объект для всех сразу.
- **Галерея на странице объекта** — объединённая: кадры всех агентств
  с подписью автора у каждого. Покупателю полезно увидеть квартиру со всех
  ракурсов, которые вообще кто-то снял.

Обложка берётся из лучшего набора целиком и не смешивается с чужой галереей
в начале: ракурсы и обработка не сойдутся, карточка будет выглядеть склеенной.

Повторы убираются по адресу файла. Одинаковые кадры, выгруженные под разными
адресами, так не поймать — для этого нужен перцептивный хеш самих изображений,
а мы их не скачиваем. Это заметное ограничение.

## Ранжирование и рекомендации

`apps/api/src/ranking/ranking.ts` — качество объявления складывается из пяти
признаков: бейдж Verificado (26%), свежесть (20%, период полураспада две
недели), полнота карточки (18%), выгодность цены за м² относительно медианы
выборки (22%), скорость ответа агентства (14%).

Платное продвижение добавляется **сверху ограниченной надбавкой**: Subida +0,06,
Destacado +0,14, Top района +0,22. Потолок ниже веса одного только Verificado —
купленный буст двигает объявление среди сопоставимых, но не вытаскивает наверх
мусор. Иначе выдача протухает, а с ней и весь трафик.

«Top района» действует только внутри своего района: купить топ по Аликанте
и всплыть в Торревьехе нельзя.

### Как устроен оплаченный показ

Продвижение **не скрывает конкурентов** и **не подменяет обычную карточку**.
Оно создаёт дополнительный слот в начале выдачи — копию объявления того
агентства, которое заплатило, с его ценой, описанием и контактами.

- Купили несколько агентств по одному объекту — наверху несколько копий,
  выше та, за которую заплатили дороже.
- Срок вышел — копия исчезает, остаётся одна карточка. Истёкшие покупки
  гасит `PromotionsService.expire()` раз в час, а выборка активных фильтрует
  по дате, так что копия пропадает сразу.
- **В оплаченной копии нет упоминания других агентств**: счётчик «продают N
  агентств» на ней всегда единица, а на её странице блок сравнения цен не
  показывается. Агентство купило показ своего предложения и не обязано
  зазывать к конкурентам.
- Помечается бейджем **Destacado** — в одной визуальной семье с Verificado,
  золото вместо зелёного, плюс тёплая подложка и золотая рамка карточки.
  Убирать пометку совсем нельзя: DSA (ст. 26) и испанский LSSI требуют, чтобы
  платное размещение было распознаваемо, а P2B-регламент — чтобы влияние
  оплаты на ранжирование раскрывалось.
- Обычная карточка того же объекта остаётся в выдаче как была: проверенная,
  при равенстве самая дешёвая. На её странице видны все предложения,
  оплаченные помечены.

Рекомендации «рядом» считаются по похожести: расстояние (38%), цена (22%),
площадь (16%), комнаты (12%), тип (7%), вид на море (5%). Радиус — 12 км:
на Коста-Бланке соседние городки стоят в 5–10 км друг от друга. Одно и то же
предложение от разных агентств в подборку не попадает.

`GET /api/listings?debug=true` возвращает разбор по слагаемым для каждой карточки.

## Логотипы агентств и продавцов

Агентство загружает логотип в кабинете, частный продавец — аватар. Пока файла
нет, показываются инициалы на фирменном цвете, поэтому выдача не разъезжается.

`POST /api/agencies/:id/logo` и `POST /api/users/:id/avatar`, multipart, до 2 МБ.
Принимаются JPEG, PNG, WebP и SVG. Тип определяется **по содержимому файла**,
а не по заголовку от клиента: исполняемый файл под видом картинки отсекается.
SVG проверяется отдельно на скрипты и обработчики событий — он текстовый и
может нести XSS. Имя файла генерируется сервером, прежний файл удаляется.

Файлы лежат в `apps/api/public/uploads/` и в репозиторий не попадают.

## CRM

`/[locale]/pro/crm` — воронка откликов и аналитика объявлений.

Стадии: `NEW → CONTACTED → VIEWING → NEGOTIATION → WON | LOST`. У отклика есть
бюджет покупателя, потребность в ипотеке, ответственный, дата следующего шага
и история заметок. Просроченные шаги подсвечиваются.

Аналитика показывает по каждому объявлению показы, клики, CTR и отклики за
30 дней, действующее продвижение и кнопки покупки Destacado / Top района.

Кабинет собственника-частника — `GET /api/crm/owner/:userId`: его объявления,
статистика и отклики без агентства.

## Ниже рынка

Главное правило витрины: объект держится в выдаче, только пока он заметно
дешевле рынка. Поднялась цена до рыночной — объект уходит сам, без ручной
модерации. Проверка идёт на каждом показе, а не один раз при заливке.

**Оценку платформа не считает.** Обе цены указывает агент: рыночную, по
которой объект идёт обычно, и свою на Casaya. Мы считаем только разницу и
решаем, пускать ли объект. Вся арифметика и порог живут в одном месте —
`apps/api/src/pricing/below-market.ts`, под тестами.

Порог — **3%**. Меньше — это торг и округление, а не «дешевле рынка»: на
250 000 € три процента дают 7 500 €, вот о такой разнице и речь. Сверху
предупреждение на **50%**: скидка больше половины почти всегда опечатка в
нулях. Порог сверяется с тем же числом, которое видит покупатель, — с
процентом, округлённым до десятых.

Правило применяется везде, где покупатель выбирает: выдача, пины на карте,
«похожие рядом». Страница объекта по прямой ссылке остаётся доступной —
ссылка из письма не должна упираться в 404, но бейджа выгоды на ней не будет.

Покупатель видит три строки: цену на Casaya, рыночную цену и разницу в евро
и процентах. Бейдж «−11%» зелёный: фиолетовый у нас значит «выбрано», золотой
— Destacado, и выгоду нельзя путать ни с тем, ни с другим.

Агентство правит обе цены в кабинете (`/pro/cabinet`). Цена не ниже рынка
сохраняется, но объект помечается как скрытый с причиной: агентство должно
видеть весь свой инвентарь, а не терять объекты из кабинета. Из фидов
рыночная цена читается из `marketPrice`, `oldPrice`, `precioantiguo` и
подобных полей; объект без неё импортируется, но в выдачу не попадает, и
превью фида показывает, сколько таких.

Площадки-конкуренты нигде не называются и не опрашиваются: публично это
«рыночная цена», `por debajo de mercado`.

## Карта

Карта объёмная и работает в двух режимах — переключает их наличие ключа
`NEXT_PUBLIC_GOOGLE_MAPS_KEY`. Код один, витрина сама выбирает подложку, а если
Google не отвечает, молча возвращается на бесплатную: портал не ломается.

### Без ключа — векторная подложка, 0 €

**MapLibre GL** на тайлах **OpenFreeMap** (схема OpenMapTiles, данные
OpenStreetMap). В слое `building` лежат `render_height` и `render_min_height`,
по ним дома вытягиваются в объём; где высота в OSM не проставлена, берётся
8 метров — такой квартал будет приблизительным. Рельеф — открытые
**AWS Terrain Tiles** (кодировка terrarium): без него виллы Альтеи и
Кумбре-дель-Соль висели бы на плоскости. Сверху небо и дымка, иначе
наклонённая карта обрывается в пустоту у горизонта. Ключей и лимитов нет.

Контур продаваемого дома берётся из **испанского кадастра** (INSPIRE WFS) —
по кадастровому номеру, а если его нет, по координатам через `Consulta_RCCOOR`
и `_Distancia`. Кадастр даёт настоящую геометрию и число этажей, поэтому дом
подсвечивается фиолетовым на реальную высоту. Метры кадастр не отдаёт, высота
считается по этажам: первый 3,6 м, остальные по 3 м, сверху 0,9 м на парапет.
Сервис медленный, поэтому ответ кэшируется в `Property.footprint` на месяц,
а его отсутствие — обычный исход, а не ошибка.

### С ключом — фотореалистичный 3D Google

`Map3DElement` из Maps JavaScript API на **Photorealistic 3D Tiles**: настоящая
текстурированная модель города. На карточке объекта режим `SATELLITE` — вывески
кафе спорят с нашей меткой, а адрес и так написан над картой; в выдаче
`HYBRID`, по подписям понятно, какой это город. Камера в выдаче считается по
габаритам всех объектов, иначе карта вставала бы на первый и остальные
оставались за кадром.

Тарификация — **по корневому запросу тайлсета**, а не по каждому тайлу: один
запрос открывает сессию на три часа. 1000 сессий в месяц бесплатно, дальше
$6 за 1000 со снижением до $2.40 на больших объёмах. В Google Cloud нужны
**Map Tiles API** и **Maps JavaScript API**, ключ обязательно ограничить по
HTTP-referrer и по списку API: он уходит в браузер и виден в исходнике.

### Метки

В обоих режимах метки свои, стандартная красная капля Google не используется.
На векторной карте — ценовые «таблетки» из макета: белые, фиолетовые у
выбранного, с терракотовой обводкой у избранного; наведение на карточку выдачи
подсвечивает пин и наоборот, клик открывает мини-карточку. В 3D Google —
фиолетовая капля на «ножке» до земли (`extruded`), иначе на наклонённой съёмке
не понять, где метка стоит; подписью идёт цена, клик в выдаче ведёт на
объявление. Карта приближается только с Cmd/Ctrl, чтобы не перехватывать
прокрутку страницы.

Координаты объектов приходят из фидов агентств (`lat`/`lng` в выгрузке CRM).
Объекты без координат на карту просто не попадают.

В приложении — тот же MapLibre и тот же стиль CARTO через
`@maplibre/maplibre-react-native`. Apple Maps и Google Maps отпали сразу:
подложку Apple Maps нельзя перекрасить под макет, а Google Maps требует ключ
и выглядит на iOS и Android по-разному.

Воркер тайлов MapLibre копируется в `public/vendor/maplibre/` скриптом
`apps/web/scripts/copy-maplibre-worker.mjs` перед `dev` и `build`: бандлер его
не эмитит, и без этого карта остаётся пустой.

## Решения, о которых стоит знать

- **Дизайн переносится инлайновыми стилями.** Значения взяты из макета без
  переосмысления. Единственное, что вынесено в `globals.css`, — ховеры
  (атрибут `style-hover` в макете нельзя выразить инлайном).
- **Числа форматируются вручную** (`groupDigits`), а не через `toLocaleString`:
  так разметка на сервере и в браузере совпадает и гидрация не ломается.
- **Импорт из фида не выдаёт бейдж Verificado.** Он появляется только после
  nota simple и видео-тура — это и есть «solo pisos reales».
- **Пропавшие из фида объекты архивируются, а не удаляются** — на них есть отклики.
- **Избранное анонимного посетителя** живёт в localStorage (в приложении —
  AsyncStorage) и переносится в аккаунт через `POST /favorites/merge` после входа.
- **Демо-фото отдаёт API** (`apps/api/public/img`), а не фронтенд: приложению
  тогда нужен один адрес вместо двух. Фото из агентских фидов — абсолютные
  ссылки на их CDN, они идут мимо.
- **Типы объектов различают виллу и дом, студию и квартиру** — так устроен
